# Deck visuals

Use this skill inside [Draft a deck from any source](../../../process/workflows.md#draft-a-deck-from-any-source). That procedure sets up the source, the answers file and the outline. This skill picks and drafts each slide's visual.

A deck's words come from its owner (the constitution, Principle III). You arrange the owner's words and figures. You never write slide text, figures or claims of your own.

## What you need

- The source material, in `docs/context/` (ignored, never committed).
- The answers file, `docs/context/answers.md`. Write each question you ask and the owner's answer word for word. The answers and the source are the only places a slide's words and figures may come from.
- The presets. Each one is an example slide file in `src/presets/slides/`, with placeholder words, made to be copied. [references/presets.md](references/presets.md) gives each preset's file, what it fits and the file itself. It is generated by `npm run presets:doc` from `src/presets/registry.ts` and the files, so it lists exactly the presets this deck has. To see them drawn, run `npm run dev` and open `/gallery`.

## A slide is a file

Each slide is a numbered file in `src/slides/`, `NN-name.tsx` (`05-results.tsx` is slide 5, with the id `results`). The number sets the order. The file has three parts:

- `meta`: the slide's `kind` (`title`, `divider`, `slide` or `closing`), its `section`, an optional `parent`, and a `layout` (`stack`, `split`, `split-end`, `center`, `statement` or `module`). A slide without a `layout` shows its title large, with `Title` in place of `Heading`.
- `copy`: every word and figure the slide shows, for each language in `src/deck/langs.ts`, the title among them. `section` and `parent` name keys of `copy`. A chart's values are numbers in `copy` too. Every language has the same keys; `npm run check` fails on a missing one.
- The default component: free JSX composed from `@/components/deck` (`Heading`, `Title`, `Body`, `Block`, and the components such as `Chart`, `Stat` or `Timeline`). It reads every word and figure from `t`, the current language's `copy`.

Never type a word or a figure into the JSX. The inline-text check (`scripts/check-inline-text.mjs`, run by `npm run test:tools` and the gate) fails on one, naming the file and line, because the trace and a second language cannot see it.

## Steps

1. **Read** the source. List its structures, in its own words: series of figures, headline figures, steps, dated events, loops, reporting lines, options against criteria, two-axis placements, quotations, claims, topics, pairs of options and images.
2. **Propose** one preset for each slide, by the [selection rules](#selection-rules). Say why it fits, and name the alternatives. See [the confirm loop](#the-confirm-loop).
3. **Draft** the slide. Copy the preset's file from `src/presets/slides/` into `src/slides/` with its number (`cp src/presets/slides/timeline.tsx src/slides/04-plan.tsx`). Put the source's and the owner's words and figures in its `copy`, replacing every placeholder. Then change the JSX freely: drop a part the owner gave no words for (a body text, a note), add or rearrange components, mix them. Ask for any missing value, unit or period. See [the trace rule](#the-trace-rule).
4. **Confirm.** The owner confirms, changes or rejects each visual. Only confirmed visuals stay.
5. **Compose when nothing fits.** Say that no preset fits, and propose a visual composed for this deck only. See [compose per deck](#compose-per-deck).
6. **Images.** Use the owner's image first. Otherwise offer to generate one. See [images](#images).
7. **Check** the draft. See [checks after drafting](#checks-after-drafting).

## Selection rules

Match the structure the source has, not the look you want. Each row names a preset as the registry does, and the file to copy; [references/presets.md](references/presets.md) shows each file.

| The source has | Propose | Copy this file | Alternatives |
| --- | --- | --- | --- |
| Categories compared: one or more values for each category | Bar chart | `src/presets/slides/bar-chart.tsx` | Comparison table; Stat cards, for up to four figures |
| A series over time: values at ordered periods | Line chart | `src/presets/slides/line-chart.tsx` | Bar chart, for a few periods; Timeline, when the points are events, not values |
| Parts of a whole: one value for each part | Donut chart | `src/presets/slides/donut-chart.tsx` | Bar chart; Stat cards, for up to four parts |
| One to four headline figures, each with its label | Stat cards | `src/presets/slides/stat-cards.tsx` | Bar chart, when the figures compare one measure; Statement, for one figure said as a claim |
| Ordered steps, each leading to the next | Process flow | `src/presets/slides/process-flow.tsx` | Timeline, when each step has a date; Agenda, when the order is only a list |
| Dated events, in date order | Timeline | `src/presets/slides/timeline.tsx` | Process flow, when the dates matter less than the order |
| A loop: stages that repeat, the last leading back to the first | Cycle | `src/presets/slides/cycle.tsx` | Process flow, when the loop is run once |
| Reporting lines: a root, the nodes under it, and theirs | Org chart | `src/presets/slides/org-chart.tsx` | The `Org` component, for one node over its roles |
| Options against criteria: one cell for each option and criterion | Comparison table | `src/presets/slides/comparison-table.tsx` | Compare, for two options; 2×2 matrix, for two criteria |
| Two axes: four quadrants, and items placed on them | 2×2 matrix | `src/presets/slides/2-2-matrix.tsx` | Comparison table |
| A quotation, word for word, with who said it | Quote | `src/presets/slides/quote.tsx` | Statement, only when the owner wants the line without its speaker |
| One claim, said large | Statement | `src/presets/slides/statement.tsx` | Quote, when someone said it; Stat cards, when the claim is a figure |
| A list of topics, in the order they come | Agenda | `src/presets/slides/agenda.tsx` | The `Points` component |
| Two options side by side, each with its points | Compare | `src/presets/slides/compare.tsx` | Comparison table, for more options or shared criteria |
| A picture with its point beside it | Image and text | `src/presets/slides/image-and-text.tsx` | Captioned image |
| One picture that carries the slide, edge to edge | Full-bleed image | `src/presets/slides/full-bleed-image.tsx` | Captioned image |
| One picture with a line that says what it shows | Captioned image | `src/presets/slides/captioned-image.tsx` | Image and text; Full-bleed image |
| Two to six pictures shown together | Image grid | `src/presets/slides/image-grid.tsx` | One image slide each |
| A structure no row fits | A composed visual | `src/presets/slides/composed/composed-visual.tsx`, as an example only | Ask the owner; see [compose per deck](#compose-per-deck) |

When a structure fits two rows, propose the first and name the second as the alternative. Feature 001's components stay available from `@/components/deck`: `Points`, `Steps`, `Facts`, `Note`, `Org`, `Fork`, `Week` and `Plan`. The placeholder deck's slide files show each one (`src/slides/03-stack.tsx` to `src/slides/12-plan.tsx`); [Slide kinds, layouts and components](../../../process/workflows.md#slide-kinds-layouts-and-components) lists them.

Each component has limits that its props' types cannot say, in `src/components/deck/limits.ts`: for example at most 12 categories in a chart, 1 to 4 stat cards, 2 to 7 steps in a flow, 2 to 8 events, 3 to 6 stages in a cycle, at most 5 columns and 8 rows in a table. In development, a component over a limit names it in the browser console and still draws what it was given. When the source has more than a preset takes, never drop or cut data silently. Propose a summary in the owner's words that the owner confirms, a split across slides, or a different preset.

## The confirm loop

For each slide:

1. **Propose.** Name the preset, quote the part of the source it draws, and say in one line why it fits (the structure from the table).
2. **Name the alternatives** from the same row, and any other row the source also fits.
3. **Ask.** Use the agent's question tool when one is available (in Claude Code, `AskUserQuestion`), with your proposal first and the alternatives as the other options. Without one, ask in plain text and wait for the answer.
4. **Keep only what the owner confirms.** On a change, draft what the owner chose. On a rejection, offer the other presets that fit. A proposal the owner has not answered is not their choice, and silence is not a yes.
5. **Write it down.** Add the question and the owner's answer, word for word, to the answers file.

Proposals may go out a few slides at a time, but each visual is confirmed on its own.

## The trace rule

- **Only the owner's words and figures, all in `copy`.** Every title, headline, label, category, series name, unit, source line, caption, alt text and stat value stands in the source or the answers file, and sits in the slide's `copy`. To shorten one, cut it to a phrase that stands there, or ask the owner for the shorter line. A placeholder left in `copy` is not the owner's word: replace it, or drop the part that shows it.
- **Figures as written.** Put each chart value in `copy` as the source writes it: `1,200` is `1200`, and `1.2M` is `1.2` with the unit the owner gives. A stat card's value is the source's own string, such as `"38%"`. Never round, convert, total, average or work out a figure. A chart of shares is plotted only when the source or the owner gives the shares.
- **Ask for what is missing.** When a value, its unit or its period is missing or unclear, ask the owner. Never infer it, and never carry a unit from one figure to another.
- **Languages.** With two or more languages, every language in `copy` has every key, each word from the owner. Numbers are not translated.

## Compose per deck

When no preset fits:

1. Say so to the owner, and name the structure no preset covers.
2. Propose a visual composed in the slide file itself. Write new JSX in the slide's default component from `@/components/deck` (the components and the slide's parts), and from Averlo parts: the ported `Panel` (`@/components/ui/primitives/Panel`), `Text` through `@/deck/text`, `Icon` through `@/deck/icon`, and the deck's tokens (`var(--deck-…)`, sized in `var(--u)`). Its words and figures sit in `copy`, as on any slide. There are no data blocks to fill. Never edit a ported file, and add no dependency without the owner's answer.
3. When the visual needs its own component, put it in `src/deck/visuals/<Name>.tsx` with typed props, and import it in the slide file from `@/deck/visuals/<Name>`, drawn in a `<Block type="custom">`. The composed visual example, `src/presets/slides/composed/composed-visual.tsx` (drawing `src/presets/examples/ComposedExample.tsx`), shows the shape.
4. Show it to the owner, and keep it only once they confirm it. It stays in this deck; the shared presets and the registry do not change.

When the owner asks for it to become a preset, follow [Promote a visual to a preset](../../../process/workflows.md#promote-a-visual-to-a-preset).

## Images

1. **The owner's image first.** Ask for it, its alt text and its source and licence. Put it under `public/images/`, set the component's `src` to `/images/<file>` in the JSX (a path, not a word), put its alt text and caption in `copy`, and add its row to `docs/licences.md` in the same commit. If the repository is public, ask whether the image may be published; an image that may not be redistributed is not committed.
2. **Otherwise, offer generation.** Say that the slide has no image and ask whether the owner wants one generated. If yes, ask which image generator they have available now, as an open question: do not list, suggest or assume one. Generate only on the owner's yes, with the generator they name, and show the result before it stays.
3. **Record a generated image.** Its row in `docs/licences.md` gives the generator's name and the date as its source, and the generator's terms as the owner states them as its licence.
4. **Until then, the placeholder.** An `Image` without `src` shows the template's placeholder. If the owner declines, or has no generator, say so and keep the placeholder. Never fetch, search for or download an image yourself.

`npm run scan:public` fails on any image without a licence row.

## Checks after drafting

1. **Trace.** Read every slide's `copy` against the source and the answers file: its text, its visuals' labels, and its chart and stat figures. Anything that does not trace goes back to the owner as a question. `tests/docs/workflow-trace.spec.ts` applies the same rule, labels and figures included, to every slide file's `copy`, and to the template's dry run (`tests/fixtures/drafted-slides/`).
2. **No inline text.** `node scripts/check-inline-text.mjs` passes: every word and figure is read from `t`.
3. **Fit.** Open each slide at 390 px and 1440 px wide (`npm run dev`). Every visual fits inside its stage; in development, an overflowing slide and a component over its limits are named in the browser console. A visual that does not fit goes back to the owner with a shorter line, a split or another preset; never shrink or cut the owner's words.
4. **Gate.** Run `npm run gate` ([Run the gate](../../../process/workflows.md#run-the-gate)). Report any check that did not run as not run.
